## Case B: one forced choice out of two

This document has two subjects, two sisters. The old schema only allows one key per subject, so I forced it: two top-level keys (黃倩儀, 黃倩鴻). The other option: one key, drop the sister, deletes her whole story. Which is correct? The event they share (founding a school together) had to be written twice, once for each sister (`huangqy_005_SHARED` / `huangqh_003_SHARED)`, because `event_relations` can't point from one subject's key to the other's. New-schema version (`/annotations/annotations_enc_exp_cmn_SPSP192708311019.json`) fixes this: the key is now a corpus path, not a person, so both sisters fit in one list and nothing needs to be forced.
